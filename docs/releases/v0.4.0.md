Windows now draws agent cards sent as A2UI v1.0 messages, as web and Apple do, by adapting them into Ouro's composed tree (ourostack/ouro-ui-windows#22).

- **`OuroA2UI`** (in `Ouro.Actions`) ports core's A2UI adapter (`a2ui.mts`, core v0.19.0; unchanged in v0.20.0).
  - `ValidateMessages` checks a stream of `createSurface`, `updateComponents`, `updateDataModel` and `deleteSurface` messages against the app's catalog. Its problems come in A2UI's error format, word for word as core writes them.
  - `ResolveMessages` gives each surface's composed tree and data model, with core's rules. A button binding stays a binding only when a field writes that exact path, and a value read from data is never followed as a binding. A button's `@label` goes last, a pointer through `__proto__`, `constructor` or `prototype` is refused, and every name is the catalog's own.
  - `ActionMessage` wraps a person's press in A2UI's action message. `TryReadToolResult` reads `structuredContent.a2ui`, and `McpAppToolResult` writes it.
  - A surface may go at most 24 components deep, resolve to at most 5,000 nodes, and copy at most a million characters out of its data (#25). Core has no such limits yet. Without them, a long chain of child ids would overflow .NET's stack, and a template over a large data model could exhaust memory.
- **`OuroComposedSurface.ShowA2UI`** draws a stream once its tree passes the kit's own `OuroComposed.ValidateTree`, so every button is exactly the catalog's. A failing stream shows the same "This card can't be shown" alert and returns the problems. `OnA2UIAction` receives each press as A2UI's action message.
- **Ouro Shop** shows the same card arriving as A2UI messages (`--page a2ui`, `Composed/card.a2ui.json`).
- **README**: a new "Agent cards" section covers both formats, how to wire each from a tool result, and what's still missing.
- **Builds on .NET 11.** The `windows-latest` image now resolves .NET SDK 11. Its WinRT source generator rejects a collection expression that targets a read-only interface, so the kit and Ouro Shop write those as arrays (#24).

## How it was checked

- **Unit tests** (CI's `actions` job): all 13 of core's A2UI conformance cases resolve to their `expect`, byte for byte, and every tree they give passes the tree validator. Core's adapter tests are ported too.
- **On `windows-latest`** (the `windows` job): UI Automation reads the A2UI card exactly as the composed card, all 24 elements. A write press sends A2UI's action message and runs; a consequential press asks first, then sends it confirmed; a person-only press hands off and sends nothing.

The limits in v0.2.0's notes still hold, and the README lists what A2UI support still lacks.
