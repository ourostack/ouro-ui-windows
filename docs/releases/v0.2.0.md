Windows draws Ouro's composed tree: the interface an agent composes for a person, as validated data, limited to the app's catalog, where every button is one of the app's declared actions with its consent class. Web and Apple drew it already; Windows now draws it with its own controls.

## What's in it

- **`OuroComposedSurface`** (`Ouro.UI.Windows`) draws an agent's tree only once it validates against the app's catalog. Send it as an MCP tool result's `structuredContent.ouro`, and read it with `OuroComposedResult.From`.
  - Read and write buttons press at once.
  - A consequential button opens a dialog with each prepared value under its label, with Cancel as the default, and presses only when the person confirms.
  - A person-only button hands the person to the app's own screen and never presses.
  - Fields write the person's answers into the data model, and a button bound to a field sends what they entered.
  - Every catalog component is drawn with Ouro HX's look, and follows light, dark, a contrast theme, the text size and the animation setting.
- **`OuroComposed`** (`Ouro.Actions`) is core's `composed.mts` in C#: the catalog's components, `ValidateTree`, `ActionButtonProps`, `ResolveButton`, `PersonPress` and JSON Pointer reads and writes. It is plain .NET, so it runs off Windows too.
- **Four more components** from core's specs: `OuroTextField`, `OuroCheckbox`, `OuroSeparator` and `OuroDescriptionList`. Each has its automation peer and passes every claim core makes for it.
- **Core v0.18.0.** The kit vendors core's composed tree, its catalogs and its conformance cases. The cases live only in core's source tree, so they come from the tag and are checked by SHA-256 against it.
- **Ouro Shop** has a second gallery page (`--page fields`) and a card its agent composed (`--page composed`), with its catalog generated from its actions.

## How it was checked

- **On Ubuntu** (`actions`): the C# port against core's conformance cases. Every valid tree must decode and validate. Forged trees must fail: a relabelled button, a loosened consent, a dropped confirm sheet, input on a person-only action, an unknown component. The port's components must match core's catalog.
- **On `windows-latest`** (`windows`): every claim core makes for the four new components, in light, dark, a contrast theme, with animations off and with text at 225%. CI then drives Ouro Shop's composed card through UI Automation:
  - it reads every component, including heading levels;
  - it types into the fields, ticks the box and picks an option;
  - it presses a write button, cancels then confirms a consequential one, and presses a person-only one, which sends nothing.

## Known limits

- **A2UI messages aren't read on Windows.** Send the tree itself; core's A2UI adapter turns A2UI messages into that same tree, but this kit doesn't include it.
- **The surface's buttons are the person's.** Nothing in the surface lets an agent press; agents act through App Actions and the MCP server. UI Automation can still press any Windows button, as with person-only buttons (docs/person-check.md).
- TextField has no password type, Clear button or large size yet.
- The free runner's limits from v0.1.0 still hold. It has no App Actions runtime, Agent Registry or Mica. The packages are on GitHub Packages and attached here; nuget.org is pending.
