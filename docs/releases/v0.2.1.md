A fix to v0.2.0's composed tree, from core v0.18.1 (ourostack/ouro-ui-core#88): a confirm sheet now shows the person what will be sent.

- **Each confirm-sheet row is checked against the catalog's.** `OuroComposed.ValidateTree` and so `OuroComposedSurface` refuse a tree whose confirm sheet differs from the rows the catalog gives for the prepared input: a row's value changed, a row dropped or relabelled, or the real value hidden in `raw` on a field that isn't an id. Only an id field (one with `shownAs`) may show a name, beside the id that is sent.
- **A button input the catalog's action doesn't declare is refused.** It would be sent with no row on the sheet.
- **The app's label resolver names only an id.** `ActionButtonProps` asks it only for fields with `shownAs`; every other row shows exactly what will be sent.
- Core v0.18.1 is vendored by tag and SHA-256.

Unit tests on CI's `actions` job cover each forged sheet and the undeclared input; each fails without the fix. The `windows` job draws and presses Ouro Shop's composed card as before. The limits in v0.2.0's notes still hold.
