A fix to the composed tree, from core v0.18.2 (ourostack/ouro-ui-core#91): no pointer reaches an object's prototype, so Windows refuses the same trees every other kit refuses.

- **A field or a bound input can't point through `__proto__`, `constructor` or `prototype`.** `OuroComposed.ValidateTree`, and so `OuroComposedSurface`, refuses such a pointer, absolute or relative. `OuroPointer.Set` writes nothing through one. `OuroPointer.IsSafe` and `OuroPointer.IsData` are new.
- **Names stay the catalog's own.** A component, action, input field or prop name a sender chooses is the catalog's only when the catalog itself has it. `OuroComposedCatalog.Load` accepts only Ouro HX's own component names. C# already worked this way; tests now pin it.
- Core v0.18.2 is vendored by tag and SHA-256.

Unit tests on CI's `actions` job cover each case; the pointer test fails without the fix. The limits in v0.2.0's notes still hold.
