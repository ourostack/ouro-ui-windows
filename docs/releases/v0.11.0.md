This release settles the long swipe on a side with several actions (#71): WinUI's SwipeControl can't commit the first action there, because its Execute mode throws on more than one item and its Reveal mode has no long-swipe commit. A swipe still reveals the actions to press, and the actions button and menu always reach every action. `OuroListRules.SwipeCommits` holds the rule, with a test; a side with one action still runs it on a swipe.

**Known gaps:** The long swipe on a side with several actions stays a WinUI limit. Table's `rowHref` rows raise a press the app handles, as Windows has no links to follow.

**Checked on:** CI, on `windows-latest` and `ubuntu-latest`. That is Windows Server, not a Windows 11 client (RELEASING.md).
