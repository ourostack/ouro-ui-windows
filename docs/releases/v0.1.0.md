The first release of Ouro UI for Windows: four of core's components as WinUI 3 controls, and the agent doors, all from ouro-ui-core v0.12.0's `defineAction`.

## What's in it

- **`Ouro.UI.Windows`**: `OuroButton`, `OuroBadge`, `OuroCard` and `OuroItem`. Each follows light and dark mode, a Windows contrast theme, the text size and the animation setting, and draws from core's tokens through one colour path. An `OuroButton` with an `Action` runs it through `Ouro.Actions`.
- **`Ouro.Actions`**: one runtime for every door. It checks input against the schema, keeps idempotency keys, audits every call, asks the person before a consequential action an agent prepared (No is the default), and answers core's typed refusal for a person-only action at every agent door. It also reads App Action URIs and serves MCP.
- **Ouro Shop**: a sample MSIX whose buttons people press and agents call. It registers its App Actions and an MCP server for the On-device Agent Registry, and has a gallery of every tone and variant.
- Core's component specs and `OuroTokens.xaml` are attached beside the packages.

## How it was checked

On the free `windows-latest` runner, CI builds, packages and installs the MSIX. It then reads the window through UI Automation in light, dark, a contrast theme, with animations off and with text at 225%. It checks every claim core makes for each component and samples pixels against what each control says it drew. It also runs the X-ray (agents and people see the same actions), answers the MCP confirmation and measures launch, memory and press latency. The run's `windows-evidence` artifact holds the screenshots and tables.

## What the free runner can't show

The runner is Windows Server 2025. It has no App Actions runtime (the catalog answers "Server execution failed"), no On-device Agent Registry (`odr.exe` needs Windows 11 build 26220.7262 or later) and no Mica. CI proves the package registers both doors and that they behave. It can't prove that Windows lists them to agents. A Windows 11 client check would add the system catalog, `odr.exe mcp list`, an agent calling through the registry, and Mica in the screenshots.

## Known limits

- The packages are attached to this release; nuget.org publishing is pending (RELEASING.md).
- An unpackaged app needs `<EnableMsixTooling>true</EnableMsixTooling>` so its `resources.pri` is written; without it the controls draw nothing.
- Requiring Windows Hello before a person-only action is built and off by default; docs/person-check.md is the open decision.
- The Ouro Shop MSIX is signed with a self-signed certificate made in the release run; install its `.cer` into Trusted People first.
